# Workflow

## 1. Understand Lambda Before Creating It

Lambda is a compute service, like EC2 is also compute.

The difference is the operating model:
- EC2 gives a virtual server that keeps running until I stop or terminate it.
- Lambda runs a function only when an event invokes it.
- With EC2, I think about instance size, OS, patching, SSH, storage, and server uptime.
- With Lambda, I think about handler code, event input, permissions, timeout, memory, and logs.

Beginner decision rule:

```text
Use Lambda for short event-driven work.
Use EC2 when I need a long-running server or full machine control.
```

## 2. Create The Function

The basic function needs:
- Function name
- Runtime, such as Python
- Handler, such as `lambda_function.lambda_handler`
- Execution role
- Code

The execution role is important because Lambda itself needs permission to write logs to CloudWatch.
The common beginner policy for logging is `AWSLambdaBasicExecutionRole`.

## 3. Test With A Small Event

A Lambda event is input data.

For a manual console/CLI test, the event can be simple JSON:

```json
{
  "source": "aws-learning",
  "message": "hello"
}
```

The handler receives:
- `event`: the input data.
- `context`: runtime metadata about the invocation, function, memory, and request.

## 4. Read Logs In CloudWatch

Lambda sends logs to a log group named like:

```text
/aws/lambda/<function-name>
```

Inside the log group:
- A log stream usually maps to an execution environment.
- `START`, `END`, and `REPORT` lines are generated by Lambda.
- `print()` and logger output appear between those lines.
- The `REPORT` line shows duration, billed duration, memory size, and max memory used.

If logs do not appear immediately, wait a few minutes and check the execution role permissions.

## 5. Tune Memory And Observe Cost/Performance

Lambda pricing is based mainly on:
- Number of requests.
- How long the function runs.
- How much memory is configured.

Memory is also the main performance lever.
When memory increases, CPU and other resources increase proportionally.

Important mental model:

```text
Higher memory costs more per millisecond, but it can reduce total duration.
The best setting is found by testing, not guessing.
```

What to observe:
- `Duration`
- `Billed Duration`
- `Memory Size`
- `Max Memory Used`

## 6. Observe Cold Start

A cold start can happen when Lambda creates a new execution environment.

Common reasons:
- First invoke after creating the function.
- Function was idle.
- New version or code deployment.
- Traffic scales beyond existing warm environments.
- Large deployment packages or heavy initialization.

Cold start is not always a problem.
It matters most for user-facing APIs where latency is visible.

The CloudWatch `REPORT` line can show `Init Duration` when an initialization phase happened.

## 7. Cleanup

For beginner labs, cleanup is part of the lab:
- Delete the function.
- Delete the log group.
- Delete the temporary role if it was created only for learning.
